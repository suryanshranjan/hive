### The owner's rules for this feature (from his interview)
The owner decided each of these himself. Encode every one that touches your area as a test before you land, follow it exactly, and do not stretch it beyond the situation it describes.

- biz_days_between: Whenever two valid dates are given, it counts the Monday-to-Friday days from the start date up to but not including the end date, so the start day counts if it is a weekday and the end day never counts, except that days that are non-working days under rule 5 (Dec 25 in particular) are never counted even when they fall on a weekday (Monday 2024-01-01 to Monday 2024-01-08 gives 5; Friday to the next Monday gives 1; Thursday 24 December to Monday 28 December with Christmas Day on the Friday gives 1).
- biz_days_between: Whenever the start and end dates are the same day, it returns 0.
- biz_days_between: Whenever the end date is earlier than the start date (the dates were entered the wrong way round), it returns 0, never a negative number and never an error, whatever the days between them are (2024-01-08 back to 2024-01-01 gives 0; Friday 6 November back to Monday 2 November gives 0).
- biz_days_between: Whenever the period contains only Saturdays and Sundays, it returns 0; a weekend start day is not counted but a weekend end day is simply excluded like any end day.
- biz_days_between: Saturdays and Sundays are skipped, and Jan 1 and Dec 25 are non-working days. Christmas Day (Dec 25) is never a working day: it is never counted in any period, in any year, whichever day of the week it falls on. No other holidays count; all other public holidays are counted as ordinary working days.
- biz_days_between: Whenever either date is NULL, it returns NULL.
- biz_days_between: Whenever either date is empty text, unreadable text (such as 'abc') or a number that is not an accepted date (such as 2024), meaning it is not written in any accepted date format, it returns -1 rather than NULL, an error or 0. Whenever either date is written in an accepted format but is a non-existent calendar date (such as 2024-02-30 or month 13), it still returns NULL rather than an error or 0. If either date is NULL, rule 6 applies and the result is NULL.
- biz_days_between: Whenever a date is written with a time after it (such as '2024-01-01 10:00:00' or '2024-01-01T09:00'), the time is ignored and only the first 10 characters are used as the date.
- biz_days_between: Whenever a date has extra text after its first 10 characters (such as '2024-01-10abc'), the extra text is ignored and the date is accepted; spaces around the date are also ignored.
- biz_days_between: Whenever a date is written in a wrong format, such as with slashes ('2024/01/10' or '11/06/2026'), without zero padding ('2024-1-10') or with a one-digit day ('2024-01-1'), it returns -1 rather than NULL, an error or 0; compact digits ('20240110') and ISO week dates ('2024-W01-1') are however accepted as valid dates, as is the number 20240110. If either date is NULL, rule 6 applies and the result is NULL.
- fmt_phone: Whenever the text contains exactly 10 digits after setting aside any extension and ignoring everything that is not a digit, it returns the number as (AAA) BBB-CCCC, whatever the separators were (dashes, dots, spaces, brackets, plus sign). If an extension was set aside, it is appended as ' x' followed by the extension digits (so '415 555 0132 ext 12' gives '(415) 555-0132 x12').
- fmt_phone: Whenever the text contains exactly 11 digits after setting aside any extension, and the first digit is 1, it drops that leading 1 and formats the remaining 10 digits as (AAA) BBB-CCCC (so '+1 555 123 4567' and '15551234567' both give '(555) 123-4567'). If an extension was set aside, it is appended as ' x' followed by the extension digits (so '1 555 123 4567 ext 89' gives '(555) 123-4567 x89').
- fmt_phone: An extension is split off from the phone number before the digits are counted. An extension is a marker word or sign such as 'ext', 'ext.', 'extension', 'x' or '#', followed by its digits (for example 'ext 12', 'x12', '#12'), and it is not counted as part of the number's digits. Whenever the number itself, without the extension, is valid (exactly 10 digits, or 11 digits starting with 1), the result is the formatted number with the extension appended as ' x' followed by the extension digits, for example '(415) 555-0132 x12'. Whenever the number itself does not end up with exactly 10 digits, it returns an empty string instead of the original text, and a trailing extension does not rescue it. This covers 11 digits that do not start with 1 (such as '2 555 123 4567'), fewer than 10 digits, 12 or more digits, and an international number like '+44 20 7946 0958'.
- fmt_phone: Whenever letters or other words are mixed in with exactly 10 digits (such as 'CALL-555-123-4567'), the non-digit characters are thrown away and the number is formatted; but a vanity number with letters instead of digits ('1-800-FLOWERS') has too few digits and returns an empty string, not the original text. The same holds for any text that has at least one digit but fewer than 10, such as a seven-digit number with no area code ('555-0132'): it returns an empty string, not the text as typed.
- fmt_phone: Whenever the area code or exchange begins with 0 or 1 (such as '0551234567' or '0155550132'), the number is still accepted and formatted in the usual way, exactly like any other 10-digit number: '0551234567' gives '(055) 123-4567' and '0155550132' gives '(015) 555-0132'. This also holds when the text is already written as (AAA) BBB-CCCC, such as '(015) 555-0132', which comes back as '(015) 555-0132' because it is formatted, not because it was passed through untouched. No check is made that the number is a valid North American number, and no such number is rejected or returned unformatted for having a 0 or 1 in those places. Only a single leading 1 on an 11-digit number is removed.
- fmt_phone: Whenever the input is NULL, it returns NULL; whenever it is empty text, it returns empty text; whenever it has no digits ('abc'), it returns the text unchanged.
- fmt_phone: Whenever the input is a plain number rather than text (such as 5551234567 or 15551234567), it is treated as its digits and formatted; a decimal number such as 5551234567.0 is not a valid North American number, because the extra digit makes 11 digits not starting with 1. It returns an empty string, not the text as typed.
- fmt_phone: Whenever the digits are written in non-Western numerals (such as Arabic-Indic digits), they are not recognised as digits and the text is returned unchanged.
- grade_letter: Whenever the score is 92 or more and no more than 100 it returns 'A'; 83 or more but under 92 returns 'B'; 71 or more but under 83 returns 'C'; 60 or more but under 71 returns 'D'; anything lower but not below 0 (0 or more but under 60) returns 'F'. - grade_letter: Whenever the score is above 100 or below 0 it returns 'X'. Exactly 0 is valid and returns 'F'. Exactly 100 is valid and returns 'A'.
- grade_letter: Whenever the score is NULL, it returns NULL.
- grade_letter: Whenever the score is text holding a number ('95', ' 85 ', '89.5', '1e2'), it is read as that number; text that starts with a number ('85%', '90abc') uses the leading number.
- grade_letter: Whenever the score is empty or blank text (nothing in it, or only spaces or other whitespace), it is not a number and returns NULL, not 'F'. - late_fee: Whenever an invoice is late by a positive number of days, the first 5 days late are free, so only the days beyond the 5th are charged. An invoice late by 5 days or fewer has no fee. For each charged day the fee is 0.5% of the invoice amount in cents, and the total is rounded down to a whole number of cents. The fee has a minimum of 500 cents, and it is capped at 20% of the invoice amount in cents, rounded down. The cap wins over the minimum, so on a small invoice where 20% of the invoice is less than 500 cents, the fee is that 20% amount. Example: 10000 cents, 10 days late: 5 charged days give 250, raised to the 500 minimum, so the fee is 500. The cap here is 2000.
- late_fee: Whenever the fee is not a whole number of cents, it is rounded to the nearest cent with exact halves rounded up. The first 5 days late are always free and are taken off before the fee is worked out, so an invoice late by 5 days or fewer has a fee of 0, whatever its amount (100 cents for 1 day late gives 0; 100 cents for 3 days late gives 0). Examples of the rounding, counting only the days beyond the 5th: 1 cent for 100 days gives 0 (95 charged days give 0.475 cents); 1 cent for 99 days gives 0; 99 cents for 10 days gives 2 (5 charged days give 2.475 cents).
- late_fee: Whenever days late is zero or negative (not late), or the invoice amount is zero or negative, the fee is 0.
- late_fee: Whenever either the amount or the days late is NULL, it returns NULL.
- Whenever days late is a fraction (such as 2.5), it is first rounded down to a whole number of days (2.5 counts as 2, 7.9 counts as 7, 0.9 counts as 0), and only then are the 5 free days taken off and the fee worked out. So 10000 cents for 2.5 days gives 0, because 2 days is within the 5 free days; 10000 cents for 7.5 days counts as 7 days, so 2 charged days give 100, raised to the 500 minimum, so the fee is 500. This applies the same way to a fractional number given as text (for example '2.5' counts as 2 days). A fractional amount (1000.5) is still used as is before the final rounding to a whole cent.
- late_fee: Whenever the amount or days late is text, a number in the text is used ('10000' and '10' give 500; '3 days' counts as 3); empty text or text with no leading number counts as 0, so the fee is 0 and not NULL.
