# Responsive task control pilot

Prepared November 19, 2026. No live journeys or model evaluations have run.
Record the candidate commit, model, test-account aliases, host, time zone and
SDK versions before starting. Use the repository's published-predictions
procedure before the first live model evaluation.

Use one dedicated Telegram owner, a test mailbox and a disposable test calendar.
The owner approves each outward action in Telegram. Compare Hive's ledger with
the provider's own sent-message and event records. Retain redacted references.

| Journey | Predicted outcome |
| --- | --- |
| Stall a tool and send status, pause and cancel | Each acknowledgement arrives within two seconds of dispatcher receipt in the controlled fixture |
| Send a duplicate update, answer an old prompt, replay an approval, cancel before execution | Zero unauthorized or duplicate effects |
| Restart with a queued request, a pending question and a pending approval | Each task is inspectable and an eligible continuation executes once |
| Lose a Gmail or Calendar response after submission, restart, then verify | Only matching readback closes the exact criterion and the retried operation is read-only |
| Switch accounts, return a mismatched receipt, or complete only half the instruction | Each unresolved outcome remains identifiable |
| Return a successful browser click, a generic MCP response, or an invented completion | Zero provider-verified tasks from these observations alone |
| Submit through SMTP and request recipient delivery confirmation | Submission is distinguished from delivery |
| Resolve an open outcome on the phone | Evidence explicitly identifies owner attestation |
| Run two projects with known reported model charges | Each task records only its own charges |

Count accepted, completed, unresolved and owner-resolved tasks. Record individual
dispatcher acknowledgement latencies, maximum latency, provider effects, duplicate
effects and reported cost per task. Record missing cost separately from billed cost.
Score every journey including failures before changing routing defaults.
